# docker-termina

[![Build image](https://github.com/termina-lang/docker-termina/actions/workflows/build-and-push.yml/badge.svg)](https://github.com/termina-lang/docker-termina/actions/workflows/build-and-push.yml)

Docker image with the Termina transpiler, the OSAL and the cross-toolchains of
the platforms that the OSAL supports.

The image is published on GHCR as `ghcr.io/termina-lang/docker-termina` and
targets `linux/amd64`, so on Apple Silicon Docker Desktop runs it with
Rosetta. The [Termina book](https://termina-lang.org/book/) describes how to
use it from the command line and as a VS Code Dev Container. The
`.devcontainer/` of a project is generated by `termina new --vscode`.

## Contents

| Platform | Toolchain |
|---|---|
| `posix-gcc` | `gcc` of Ubuntu 24.04 |
| `rtems5-leon3sf-nexysa7` | Gaisler RCC 1.3.2 (`sparc-gaisler-rtems5-gcc`), in `/opt/rcc` |
| `rtems6-zynq7000-pynqz2` | RTEMS 6.2 (`arm-rtems6-gcc` and the `xilinx_zynq_pynq` BSP), in `/opt/rtems/6` |
| `freertos10-stm32l432-nucleol432kc` | Arm GNU Toolchain 13.3.rel1 (`arm-none-eabi-gcc`), in `/opt/arm-none-eabi` |

Along with the toolchains, the image includes:

- `termina`, and the OSAL in `/opt/termina-osal` (`TERMINA_OSAL_DIR`).
- `gdb`, and `gdb-multiarch` with the GDB support of RTEMS 6.
- cppcheck 2.21.1 with the MISRA addon.
- MAST (`mast_analysis`), for `termina sched`.
- `lcov`.

## Debugging on a board

![Debugging on a board from the Dev Container](https://termina-lang.org/book/diagrams/remote-debugging.svg)

`gdb-multiarch` in the container connects to the GDB server of the board's
debug tool, which runs on the host:
[GRMON](https://www.gaisler.com/products/grmon3) for the Nexys A7, the
`hw_server` of [AMD Vitis](https://www.amd.com/en/products/software/adaptive-socs-and-fpgas/vitis.html)
for the PYNQ-Z2 and the `ST-LINK_gdbserver` of
[STM32CubeCLT](https://www.st.com/en/development-tools/stm32cubeclt.html) for
the Nucleo-L432KC. On a Linux host with `ufw`, the default policy drops the
connections that come from the containers through the `docker0` bridge. The
following rule opens the default ports of the three servers:

```sh
sudo ufw allow in on docker0 to any port 2222,3000,61234 proto tcp
```

A server started on another port needs that port in the rule. The
[debugging chapter](https://termina-lang.org/book/tooling/debugging/) of the
book describes the configuration that `termina new --vscode` generates.

## Building locally

```sh
docker build --platform linux/amd64 -t docker-termina:dev .
```

The build arguments `TERMINA_REF` and `OSAL_REF` select the branch or tag of
the transpiler and of the OSAL. They default to the tags of `TERMINA_VERSION`
and `OSAL_VERSION`.

## Layout

- `Dockerfile`: the builder stages (transpiler, RTEMS 6, cppcheck) and the
  runtime image.
- `rtems/config.ini`: the BSP configuration of RTEMS 6.
- `scripts/`: the scripts that remove from the toolchains and the RTEMS
  sources what the platforms do not use.

## Versioning

The image version tracks the Termina transpiler and the OSAL at the
`MAJOR.MINOR` level. See [`CHANGELOG.md`](./CHANGELOG.md) for the versions
bundled by each release.
